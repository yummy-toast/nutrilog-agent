# 请求级执行预算

2026-11-04实现，作用于POST /api/v1/chat。固定脚本live-smoke和food-agent-smoke仍使用原验证入口，不据此声称它们也接入预算。

## 控制方式

每个请求创建ExecutionBudget，使用System.nanoTime计算耗时；上限为6次模型决策、8次工具执行和60秒总预算。所有尝试执行前检查，工具业务失败也消耗额度。第7次模型请求、第9次工具调用在执行前拒绝。

BudgetedChatLoop直接调用ChatModel单轮API，按模型返回的工具调用逐项执行，再把ToolResponseMessage回传。只允许已注册的两个食品工具。每轮复制已配置OpenAI选项（保留实际模型及温度等），覆盖本轮工具列表、关闭重试，并将SDK超时设为min(30秒,整体剩余时间)。

模型调用在容量4、无等待队列的独立线程池中执行，Future等待也受本轮剩余时间限制。超时后cancel(true)请求中断；编排线程退出，迟到模型响应不能发起工具。未响应取消的调用在真正退出前继续占用槽位，新请求饱和时返回503，避免无限排队。应用关闭时请求停止线程池。

## HTTP错误

- MODEL_LIMIT_EXCEEDED / TOOL_LIMIT_EXCEEDED：502，达到模型/工具次数上限。
- EXECUTION_TIMEOUT：504，整体预算耗尽。
- MODEL_TIMEOUT：504，本次模型等待超时。
- MODEL_BUSY：503，4个执行槽位均被占用。
- EXECUTION_CANCELLED：503，请求等待线程被中断。
- UNKNOWN_TOOL：502，模型提出未注册工具。

## 验证

33项Java测试通过并完成verify打包。其中新增覆盖：

- 模型不断要求搜索，恰好6次模型/6次工具后拒绝第7轮。
- 一次响应提出9次工具调用，只执行前8次。
- 虚拟单调时钟已耗55秒，实际模型请求选项只剩5秒；迟到响应不执行工具。
- 协作式取消：等待超时触发线程中断，不执行迟到工具。
- 两个并发请求各自6次模型/6次工具，互不消耗额度。
- 不响应取消的4个假调用继续占用槽位，第5个被拒绝；测试最后释放假调用。
- 复制模型原配置，避免构造新选项时使用框架默认模型覆盖deepseek-chat。

真实HTTP检查2条通过：168935、200克返回260.00kcal、5.38g蛋白质、0.56g脂肪、56.34g碳水及USDA来源；独立请求“200克呢？”重新追问食品。第一次真实回归暴露选项覆盖问题，修复后通过；保留该问题的回归测试。

## 限制

不是硬实时保证：操作系统调度、JSON处理或不可中断的本地工具可能稍晚返回。当前食品工具为快速本地只读计算，工具调用前后检查预算，但不强制中断工具执行；后续如接远程工具，必须给工具本身设置超时与取消策略。

cancel(true)及SDK超时不保证远端立即停止或不计费；真实网络层取消未做故障注入验证。残留模型工作最多4个，槽位饱和期间可能持续返回503，直到底层退出。没有新增自动重试、鉴权、持久化、完整指标或会话记忆。
